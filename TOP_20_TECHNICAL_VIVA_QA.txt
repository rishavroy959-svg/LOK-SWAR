Q1. SYSTEM ARCHITECTURE & TECH STACK
--------------------------------------------------------------------------------
[Question]: What is the overall end-to-end technical architecture and tech stack of Lok Swar?

[Quick Viva Answer]:
"Lok Swar is an API-first microservices platform consisting of a zero-build React 18 frontend, a Python multi-threaded REST gateway (Port 8000), a standalone FastAPI IVR telephony engine (Port 8001), and a dual-persistence database layer using MongoDB Atlas with an atomic JSON cache failover."

[Deep Technical Detail]:
- Client Layer: React 18 Standalone, Tailwind CSS, Leaflet.js GIS mapping, Web Speech API (speechSynthesis & webkitSpeechRecognition).
- Core Backend Gateway: Python native ThreadingHTTPServer in `server.py` serving 49 REST endpoints. Runs in-process with AI, GIS, and Optimization modules to avoid IPC (Inter-Process Communication) latency.
- Telephony Microservice: FastAPI + Uvicorn in `ivr/main.py` receiving Twilio TwiML webhooks and dispatching SMS alerts via Fast2SMS Indian SMS gateway.
- Data Layer: Dual-Persistence (`db/mongo.py`). Primary = MongoDB Atlas (PyMongo); Secondary = thread-safe `db/local_store.json` atomic flat-file cache for complete offline survivability.

[Examiner Cross-Question Tip]:
If asked: "Why not use Django or Flask?"
Answer: "Django has high framework overhead (ORM, migrations) which slows down raw API throughput. Native ThreadingHTTPServer gives zero-dependency footprint and microsecond execution for in-process math and AI calls."

Q2. MULTI-LINGUAL ASR & DIALECT HANDLING
--------------------------------------------------------------------------------
[Question]: How does your Speech-to-Text (ASR) engine handle unstandardized rural dialects like Bhojpuri or Odia?

[Quick Viva Answer]:
"We utilize a dual-stage ASR pipeline: first, localized acoustic modeling via Web Speech API (hi-IN, or-IN, bn-IN), followed by an in-house Regex Token Transducer in Python that maps colloquial grammatical markers and idioms into formal administrative root semantics."

[Deep Technical Detail]:
1. Acoustic Capture: Uses ISO language codes (`hi-IN`, `or-IN`, `bn-IN`) with continuous audio stream buffers.
2. Dialect Transducer (`services/translation_ai.py`): Scans for grammatical dialect markers:
   - Bhojpuri: 'बा', 'नइखे', 'गइल', 'पुलवा', 'चापाकल'
   - Odia: 'ଭାଙ୍ଗିଯାଇଛି' (bhangijaaichi), 'ପାଣି ନାହିଁ' (pani nahin)
   - Bengali: 'ভেঙে গেছে' (bhenge geche), 'জল আসছে না' (jol ashche na)
3. The normalized semantic tokens are passed to the downstream NMT and classification models.

[Examiner Cross-Question Tip]:
If asked: "What if the citizen speaks with background noise or low-quality microphone?"
Answer: "Web Speech API utilizes client-side Web Audio API noise suppression and echo cancellation constraints (`echoCancellation: true, noiseSuppression: true`)."

--------------------------------------------------------------------------------
[Question]: How does your translation pipeline work, and what guarantees zero downtime in low-bandwidth rural areas?

[Quick Viva Answer]:
"We implemented a deterministic 4-Tier Fallback NMT architecture: Google Mobile Translation Engine -> Google GTX NMT API -> MyMemory Multi-Lingual API -> Offline Civic Phrasebook Dictionary."

[Deep Technical Detail]:
- Tier 1: Google Mobile Translation Client (low-latency, optimized for quick payloads).
- Tier 2: Google GTX NMT endpoint with automatic language pair detection.
- Tier 3: MyMemory API (`https://api.mymemory.translated.net/get`) with ISO pair routing (`bho|en`, `hi|en`, `or|en`).
- Tier 4: Offline Rule-Based Civic Phrasebook (`LOCAL_FALLBACK_DICT`). Maps critical civic tokens (e.g., 'chaapaakal' -> 'Handpump', 'puliya' -> 'Culvert/Bridge', 'bijli' -> 'Electricity') directly to English with zero network requests.

[Examiner Cross-Question Tip]:
If asked: "What is the time complexity of the fallback?"
Answer: "Worst-case network timeout is capped at 1.5 seconds per tier using Python `urllib.request` socket timeouts before gracefully dropping to the Tier 4 local dictionary (O(1) dictionary lookup)."

Q6. SPATIAL PROXIMITY & HAVERSINE DEDUPLICATION
--------------------------------------------------------------------------------
[Question]: How does the system prevent duplicate tickets and calculate the 50km civic radar?

[Quick Viva Answer]:
"We apply the Haversine Great-Circle spherical trigonometry formula. Any new complaint within a 500-meter radius matching an existing open category is converted into a '+1 Civic Endorsement' rather than creating a duplicate ticket."

[Deep Technical Detail]:
Haversine Formula:
  dLat = radians(lat2 - lat1)
  dLng = radians(lng2 - lng1)
  a = sin²(dLat / 2) + cos(lat1) * cos(lat2) * sin²(dLng / 2)
  c = 2 * atan2(√a, √(1 - a))
  Distance = R * c  (where Earth's radius R = 6371.0 km)

Implementation in Backend:
- `/api/grievances/nearby`: Computes distances to all open tickets in under 4ms.
- Deduplication Filter: If `Distance <= 0.5 km` AND `Category == Existing_Ticket.Category`:
  System executes atomic `$inc: { upvotes: 1 }` on the existing ticket and appends the citizen's mobile hash to prevent duplicate voting.

[Examiner Cross-Question Tip]:
If asked: "Why not use MongoDB 2dsphere index?"
Answer: "We support MongoDB 2dsphere `$nearSphere` when connected to Atlas, but the in-memory Haversine function guarantees identical spatial query capability during local JSON cache failover mode."

Q7. DATABASE DESIGN: MONGODB & DUAL PERSISTENCE FAILOVER
--------------------------------------------------------------------------------
[Question]: Why did you select MongoDB over a relational SQL database, and how does Dual Persistence work?

[Quick Viva Answer]:
"Grievance data is polymorphic (containing audio URLs, drone telemetry bounding boxes, sensor arrays, and upvote hashes), which would require 6+ relational SQL joins. Dual Persistence ensures that if MongoDB Atlas goes down, the system instantly fails over to an atomic local JSON datastore."

[Deep Technical Detail]:
- Polymorphic Document Schema: Grievance document holds `audio_url`, `gps_coords: {lat, lng, accuracy}`, `ai_metadata: {urgency, category, confidence}`, `drone_telemetry`, and `endorsements: []`.
- Dual Persistence Architecture (`db/mongo.py`):
  1. Primary: PyMongo connection pool with a 2000ms serverSelectionTimeoutMS.
  2. Fallback Detector: On `ServerSelectionTimeoutError` or network drop, `get_db()` automatically switches to `LocalStore` instance.
  3. `LocalStore`: Thread-safe, atomic file write (`tempfile` + `os.replace`) operating on `db/local_store.json`. Exposes identical CRUD interface (`find`, `find_one`, `insert_one`, `update_one`).

[Examiner Cross-Question Tip]:
If asked: "What happens when internet connection recovers?"
Answer: "A background synchronization worker reads un-synced documents from `db/local_store.json` using timestamp markers and performs an `upsert` into MongoDB Atlas."

Q11. 0/1 KNAPSACK MATHEMATICAL BUDGET OPTIMIZATION
--------------------------------------------------------------------------------
[Question]: Why use a 0/1 Knapsack Mixed-Integer Linear Programming (MILP) algorithm for treasury allocation?

[Quick Viva Answer]:
"Public works budgets are strictly capped (e.g. ₹5 Crore), while grievance repair estimates exceed ₹25 Crore. Traditional manual allocation results in political bias. The 0/1 Knapsack algorithm mathematically selects the optimal subset of projects that maximizes societal impact under the budget ceiling."

[Deep Technical Detail]:
Mathematical Formulation:
  Maximize:
    Z = SUM(j=1 to N) [ Utility_Score_j * Affected_Population_j * x_j ]

  Subject to:
    SUM(j=1 to N) [ Cost_j * x_j ] <= Total_Treasury_Budget
    SUM(j=1 to N) [ Tribal_Rural_Flag_j * x_j ] >= Min_Rural_Quota
    x_j ∈ {0, 1}

- Binary Variable: x_j = 1 means project 'j' is allocated funds; x_j = 0 means deferred to next budget cycle.
- Time Complexity: O(N * W) using Dynamic Programming table, or solved via branch-and-bound linear solver.

[Examiner Cross-Question Tip]:
If asked: "Why not use a simple greedy algorithm (highest utility first)?"
Answer: "The greedy algorithm does not guarantee an optimal solution for the 0/1 Knapsack problem and easily wastes leftover budget. Dynamic programming / MILP guarantees the global mathematical optimum."

Q12. TRIBAL & RURAL EQUITY CONSTRAINT
--------------------------------------------------------------------------------
[Question]: How does your Knapsack solver prevent urban bias, where high-density cities always win over low-density tribal villages?

[Quick Viva Answer]:
"We enforce a statutory hard constraint in the MILP solver: `SUM(Tribal_Rural_Flag_j * x_j) >= Min_Rural_Quota`. This legally mandates that a minimum percentage of the budget must be allocated to remote tribal panchayats regardless of population size."

[Deep Technical Detail]:
- Problem: If utility depends on population, a city pothole affecting 50,000 people will always beat a collapsed tribal footbridge affecting 800 villagers.
- Technical Fix:
  1. Rural Weighting: Multi-Attribute Utility Theory (MAUT) applies an 'Infrastructure Gap Multiplier' (up to 2.5x) for locations lacking alternative roads/hospitals.
  2. Hard MILP Constraint: Forces the branch-and-bound solver to satisfy the statutory quota before maximizing the objective function.

[Examiner Cross-Question Tip]:
If asked: "What happens if no rural project exists?"
Answer: "The solver checks slack variables; if rural project queue is empty, excess quota safely cascades back to the general fund."

[Quick Viva Answer]:
"We adhere strictly to the Aadhaar Act and Supreme Court regulations: we NEVER store raw 12-digit Aadhaar numbers in plaintext. The input is immediately masked on the UI and converted into an irreversible salted SHA-256 hash in the backend."

[Deep Technical Detail]:
1. Frontend Masking: The input field masks numbers immediately: `•••• •••• 9012`.
2. Salted Cryptographic Transformation:
     Aadhaar_Hash = SHA-256(Raw_12_Digit_Aadhaar + Backend_Secret_Salt)
3. Only `Aadhaar_Hash` is stored in the database as a unique index to enforce 1-Citizen-1-Vote integrity.

[Examiner Cross-Question Tip]:
If asked: "What if someone steals your database?"

[Question]: How does Lok Swar scale from one district to all 543 Parliamentary Constituencies of India?

[Quick Viva Answer]:

3. Edge Caching: Static HTML, JS, CSS, and localized voice synthesis assets are served via Cloudflare CDN edge nodes with 99.9% cache-hit ratio.
4. Operational Cost: Entire district handling 50,000 monthly grievances operates under ₹25,000/month (~$300 USD).

If asked: "What is your API response latency under load?"
Answer: "Core REST endpoints (`/api/grievances/nearby`, `/api/ai-categorize`) respond in under 15 milliseconds because ML token transducers run in-process without multi-hop microservice latency."
